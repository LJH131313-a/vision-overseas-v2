# 启动、发布、更新与故障处理

## 一、本机启动（无需安装任何东西）

1. 打开本目录，**双击 `index.html`**。页面通过 `<script>` 标签加载数据（`data/vo-data.js`、`data/news.js`），不依赖 Python、Node 服务或数据库。
2. 项目数据保存在浏览器本机存储（localStorage）。若以 `file://` 方式打开，部分浏览器可能限制本机存储——推荐用 Chrome/Edge，或按下节通过本地静态服务/线上地址访问。
3. 「删除项目」「保存回复」等操作只影响本机浏览器数据，不影响网站文件。

> 说明：核心页面设计为无服务运行；但新闻**采集**程序需要 Python 或 GitHub Actions（见第四节）。

## 二、发布到 GitHub Pages

仓库：https://github.com/LJH131313-a/vision-overseas-v2

1. 仓库 Settings → Pages → Build and deployment → Source 选择 **GitHub Actions**。本项目使用工作流发布。
2. 将需要发布的修改提交到 main；开发分支完成审查后再合并 main。
3. Actions 中的「部署网站到 GitHub Pages」会检出最新 main，执行 208 项引擎断言和 25 项静态资源检查，只打包 index.html、favicon.svg、css、js、data，然后部署。
4. 发布地址：https://ljh131313-a.github.io/vision-overseas-v2/
5. 首次发布需要手动开通 Pages；工作流不需要个人访问令牌或 administration 权限。
6. 如需重新部署，在 Actions → 部署网站到 GitHub Pages → Run workflow 中运行，或重试失败的运行。

## 三、日常更新与回退

提交并推送页面或数据修改到 main 后自动发布。版本历史保留在 GitHub，可通过恢复旧提交后再发布回退。

新闻定时任务「更新新闻快照」保存数据后，会由 workflow_run 触发部署；不会依赖机器人 push 再触发另一个 push 工作流。修改采集器、来源配置或更新工作流，也会执行一次采集验证。

## 四、新闻定时更新（GitHub Actions）

- 工作流：`.github/workflows/update-news.yml`。**定时任务（非实时监控）**：北京时间约 **09:17 与 17:17** 各执行一次；也可在仓库 **Actions → 更新新闻快照 → Run workflow** 手动运行。
- 流程：`tools/collect_news.py` 抓取 `news/feeds.json` 中 11 个政府官方 RSS/Atom 来源 → 与既有快照合并去重（按标题+链接指纹；最多保留 1200 条、240 天窗口）→ 输出 `data/news.json` 与 `data/news.js` → 自动提交回 main → 完成后由发布工作流重新发布网站。
- 首次使用前确认：仓库 **Settings → Actions → General → Workflow permissions** 选择 **Read and write permissions**（工作流需要写回快照）。
- 部分来源失败：保留成功来源与历史新闻，来源状态表中标红显示失败原因；全部失败：完整保留最后一次成功快照并在页面新闻模块显示「采集全部失败」状态。
- 采集遵守来源站点的访问限制（标准 User-Agent、不重试轰炸、不绕过 403/429）。

### 本机手动更新（可选，需要 Python 3.10+）

```bash
python tools/collect_news.py          # 联网采集并合并
python tools/collect_news.py --offline  # 不联网，仅重建 news.js
```

没有 Python 时，可用 Node 只重建包装文件（不采集）：`node tools/rebuild_news_js.mjs`。

## 五、常见故障处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面空白 / 数据缺失 | `data/vo-data.js`、`data/news.js` 未随仓库提交 | 检查文件是否在发布分支；重新提交 |
| 新闻模块显示「快照为空或未加载」 | `data/news.js` 缺失 | Actions 跑一次采集，或本地 `node tools/rebuild_news_js.mjs` |
| Actions 定时任务没跑 | 默认分支上的工作流才会定时执行；或 Workflow permissions 未开 | 把工作流合入**默认分支**；检查 Settings → Actions 权限 |
| Actions 推送被拒 | Workflow permissions 只读 | Settings → Actions → General → Workflow permissions → Read and write |
| 某些新闻来源一直失败 | 来源网站改版或限制访问 | 页面会如实显示失败状态；人工核对来源 URL 后更新 `news/feeds.json`，不要绕过访问限制 |
| GitHub Pages 404 | Pages 尚未启用或发布未成功 | Settings → Pages 的 Source 选择 GitHub Actions，并检查部署运行 |
| 更新后看到的还是旧页面 | CDN 缓存 | 强制刷新（Ctrl+F5）或等几分钟 |
| 本机存储不可用（隐私模式） | 浏览器限制 localStorage | 用常规窗口打开；页面会提示「仅当前会话有效」 |
| 页面上出现「需要重新分析」 | 输入指纹与保存的千问回复/快照不一致 | 这是预期行为：重新生成任务、重新分析后再次保存 |

## 六、数据包重建（维护者）

原始团队交付物（产品知识包、法规数据包、正式合规项目、PolicyRadar 快照）变更后：

```bash
node build/build-data.mjs <原始交付物根目录>   # 默认取上级目录
node tests/engine.test.mjs                    # 208 项引擎回归
node tests/dom-smoke.mjs                      # 48 项页面冒烟（需 npm i jsdom --no-save）
node tests/static-assets.test.mjs             # 25 项子路径与敏感信息检查
```
